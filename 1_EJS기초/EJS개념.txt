EJS란?
- EJS(Embeded Java Script) = HTML 안에 자바스크립트 코드를 삽입해서 동적으로 웹 페이지를 생성할 수 있게 해주는 "템플릿" 엔진
- Node.js 환경에서 Express.js 같은 프레임워크와 함께 많이 사용

- 템플릿 엔진이란? 개발자는 페이지를 하나만 만들고(틀을 제공) 서버가 값을 동적으로 생성하는 엔진
    - 서버에서 데이터와 템플릿(틀)을 합쳐서 HTML을 만들어 클라이언트로 보내주는 도구
    * Pug, Nunjucks, Handlebars ... -> 고유한 문법이 존재 -> 문법을 새롭게 공부가 필요
    * EJS는 기존 JS 문법을 그대로 활용할 수 있어서 진입 장벽이 낮음 (= 자바스크립트의 문법과 똑같음)

- 특징
    1) HTML 기반 템플릿이라 웹 퍼블리셔/프론트 개발자가 익숙하게 사용 가능
    2) <% %> 구문으로 JS 코드 그대로 삽입 가능
    3) Node.js 서버 사이드 렌더링(SSR)에 적합 → SEO에도 유리 (검색 엔진에 최적화)

- 사용처: 로그인 후 메인페이지, 게시판 글 목록, 검색 결과, 댓글/리뷰 리스트
                    -> 즉, 동적 데이터 표시가 필요한 대부분의 HTML 페이지에 사용

[알아두면 좋은 웹 지식]
- EJS를 통해서 페이지를 제작 (동적 생성) -> SSR(Sever Side Rendering)
- SSR은 HTML 파일을 서버가 제작 후 -> 클라이언트에게 보내는 방식
- SSR 장점
    1) 빠른 초기 로딩 속도 -> 클라이언트에서는 바로 출력이 가능
    2) SEO 최적화: 검색 엔진이 HTML 파일을 읽어들일 때, 속도가 빠르다 -> 내용을 채워서 넘기기 때문에

- CSR(Client Side Rendering) -> 페이지를 제작하는 곳이 클라이언트
- 서버가 비어있는 html과 태그를 생성하는 JS 코드를 클라이언트에게 전달 -> 클라이언트 제작
    * React, Angular, Vue ...

- CSR 장점
    1) 동적 UI 생성에 효율적 -> 특정 부분만 빠르고 쉽게 수정이 가능함 (비동기 통신)
    2) 프론트엔드와 백엔드가 역할 구분이 확실히 가능함

- 최신 트렌드 SSR + CSR 하이브리드 렌더링을 선호
- 초기 페이지는 SSR 기법 + 특정 내용을 바꿀 때는 CSR 기법
* Next.js, Svelte



토스
- 네이티브 앱 개발(Android, ios) + CSR + SSR 
    1. 네이티브 앱 개발 (Android, iOS)
        - 네이티브 앱: 특정 플랫폼(OS)에 맞춰 전용 언어·도구로 개발하는 앱
            - Android → Java / Kotlin
            - iOS → Swift / Objective-C
        - 장점: 성능 최적화, 플랫폼 기능(푸시 알림, 센서, 카메라 등) 활용 가능
        - 토스는 안드로이드, iOS 모두 네이티브 방식으로 개발 → 속도, 보안, 안정성 확보

    2. CSR (Client Side Rendering)
        - 클라이언트 사이드 렌더링 = 브라우저(클라이언트)가 JS로 화면을 그림
        - 초기에는 빈 HTML + JS 번들만 받고, 이후 JS가 실행되며 DOM 생성 → 화면이 나타남
        - 장점: 사용자 경험(UX)이 부드럽고 앱처럼 동작
        - 단점: 첫 화면 로딩이 느림, SEO 불리

    3. SSR (Server Side Rendering)
        - 서버 사이드 렌더링 = 서버가 완성된 HTML을 만들어 전달
        - 브라우저는 전달받은 HTML을 바로 렌더링 → 첫 화면이 빠르게 뜸
        - 장점: 초기 로딩 속도↑, SEO 최적화
        - 단점: 서버 부하↑, 클라이언트 전환 시 새 요청 필요

    4. 토스 맥락에서 이 말의 의미
        - 토스는 **네이티브 앱(Android/iOS)**을 기반으로 하지만, 내부적으로는 웹뷰·웹 기술도 같이 활용합니다.
        - 따라서 CSR + SSR 조합을 적절히 활용:
            - SSR → 로그인 직후 메인화면, SEO 필요한 영역 (웹서비스, 이벤트 페이지)
            - CSR → 앱 내부 전환, 게시판/피드 등 동적 데이터 갱신
